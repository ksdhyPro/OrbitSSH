# OrbitSSH AI Agent 架构

## 1. 设计目标

OrbitSSH AI Agent 在 Electron 主进程内完成模型请求、数据暴露检查、命令安全审查、审批和命令执行。Renderer 只负责会话展示和用户交互，不能绕过主进程策略直接批准或执行 AI 命令。

Agent 支持三种模式：

- `ask`（逐命令审批）：每条格式有效的命令都需要用户批准。
- `auto`（自主执行）：只读查询和常规低中风险操作自动执行；删除、Docker 变更、提权、敏感数据读取等高风险操作需要批准，默认使用此模式。
- `full_access`（完全访问）：授权连接范围内、格式有效的命令直接执行，不产生审批。

旧版设置中的 `full` 实际代表“自动只读”，读取时迁移为 `auto`，避免升级后静默放大权限。

## 2. 模块职责

| 模块 | 职责 |
| --- | --- |
| `ai-agent.ts` | Agent 循环、执行预算、命令卡状态、请求取消与审批恢复编排 |
| `ai-permission-policy.ts` | 合并三档授权、模型风险标记和命令策略，输出执行、审批或拒绝决策 |
| `command-policy.ts` | Shell 命令规范化、只读白名单、高风险规则与复合命令审查 |
| `ai-data-policy.ts` | 独立审查凭据源、敏感文件和可能泄露秘密的查询 |
| `ai-provider.ts` | 在线模型与 Codex CLI 适配、超时、重试和工具调用数量约束 |
| `ai-response-parser.ts` | SSE/JSON 响应解析和工具参数校验 |
| `ai-context.ts` | 稳定系统指令、不可信上下文隔离、工具消息重建、脱敏及上下文预算 |
| `ai-execution-budget.ts` | 命令数量、总耗时和重复无进展检测 |
| `ai-saved-server-command.ts` | 通过已保存连接执行受控的跨服务器命令，并在连接前复核权限 |
| `ai-approval-store.ts` | 一次性审批、五分钟 TTL 和按标签页清理 |
| `ai-input.ts` | IPC 输入结构、请求身份、标签页一致性和长度限制 |

共享类型位于 `src/shared/ai.ts` 和 `src/shared/settings.ts`，主进程 IPC 入口位于 `src/main/ipc/ai-ipc.ts`。

## 3. 请求与执行流程

1. Renderer 为每次发送或审批恢复生成新的 `requestId`，并携带固定的 `conversationId`、标签页、模式、用户消息和服务器上下文。
2. 主进程验证完整输入，并确认 `input.tabId` 与 `context.tabId` 一致。同一标签页的新请求会终止旧请求；取消操作必须匹配当前 `requestId`。
3. Agent 构建模型请求：
   - System 消息只包含稳定、可信的行为和安全规则。
   - 服务器名称、当前路径、连接状态和执行预算位于单独的“不可信运行上下文”用户消息中。
   - 最近终端输出默认不发送；用户开启后先脱敏再截断。
   - 已执行动作使用标准 `assistant.tool_calls` 与 `tool` 结果消息重建，保留同一个工具调用 ID。
4. 模型每轮最多产生一个动作：
   - `run_shell_command`：在当前终端执行命令。
   - `run_saved_server_command`：通过本地保存的连接操作用户明确提及的其他服务器。
5. 主进程先执行数据暴露策略，再执行命令策略：
   - `allow_readonly`：明确命中安全只读白名单。
   - `allow_autonomous`：未命中高风险规则，可由自主执行模式直接运行。
   - `requires_approval`：明确高风险或敏感命令，由授权档位决定审批或直接执行。
   - `deny`：空命令、超长命令、非法空字符或无法安全解析的命令，任何档位和审批都不能绕过。
6. 权限模块把授权档位、模型风险和命令策略合并为 `execute`、`requires_approval` 或 `deny`。`deny` 会作为结构化工具错误反馈给模型，最多允许 3 次修正；耗尽后停止本轮。
7. 命令执行结果脱敏后返回模型，Agent 根据结果继续分析或总结。单轮最多执行 12 条命令，总时长最多 10 分钟，并检测重复无进展。

## 4. 执行边界

### 当前服务器与工作目录

- 当前路径随请求显式绑定到命令执行，SSH 使用安全引用的 `cd -- <path> && <command>`，本地终端使用进程 `cwd`。
- 工作目录必须是绝对路径；路径未知时使用连接的登录默认目录。
- 命令卡展示实际执行目录，避免模型语义与终端执行位置不一致。
- 复合只读命令会逐段审查，但仍按原始完整命令执行，保留 Shell 的 `&&`、管道和退出码语义。

### 跨服务器操作

- 模型不能通过当前服务器执行 `ssh`、`scp` 或 `sftp` 跳转。
- `run_saved_server_command` 只能使用本地已保存连接，并且要求用户明确提及目标服务器。
- 跨服务器命令与当前服务器使用相同的三档权限；执行适配器在建立连接前再次复核命令策略、模式和审批状态。
- 服务器名称有多个匹配时拒绝执行，要求使用完整名称。

## 5. 安全与隐私

### 命令和数据策略

- 命令最大 4096 字符；NUL、未闭合引号和未完成转义直接拒绝。
- 自主执行模式允许常规文件写入、依赖安装、普通服务重启和未知命令，减少日常审批打断。
- 删除、Docker 变更、提权、持久化任务、集群变更、破坏性数据库命令和敏感数据读取在自主执行模式下强制审批。
- 完全访问模式不产生审批，但仍保留命令长度、格式校验、执行预算、超时、取消和审计记录。
- 自主执行模式下，模型返回 `high` 会强制进入审批；模型风险标记不能把本地高风险规则降级。

### 提示词与输出

- 动态上下文和工具结果都明确标记为不可信数据，不能覆盖 System 规则。
- 工具结果和终端上下文使用同一套凭据脱敏规则，覆盖常见 Token、密码、Authorization、Cookie、URL 凭据和 PEM 私钥。
- 最近终端输出最多 3000 字符；单条工具结果最多 4000 字符；工具结果合计最多 24000 字符。
- 模型历史最多使用最近 8 条，合计最多 16000 字符。
- 应用日志只记录长度、状态、模型和工具名，不记录原始模型响应、完整命令或终端上下文。

### 审批、并发与取消

- 审批 ID 绑定标签页、对话和完整命令，只能成功取出一次。
- 审批五分钟后主动过期；新请求、终端关闭、批准或拒绝都会清理对应状态。
- Renderer 按 `tabId + conversationId + requestId` 路由消息、流式片段和命令卡，不依赖当前激活标签页。
- 每个标签页独立维护草稿、错误和活动请求；切换标签页不会误取消或串接另一标签页的回复。
- 取消或超时会停止本地子进程；SSH 命令会尝试发送 `INT` 并关闭 Channel。
- 命令卡使用 `cancelled` 表示终止，不会遗留 `running` 状态。

## 6. 模型适配

- OpenAI 兼容接口使用标准工具调用消息；单轮返回多个工具动作或无效工具参数时会拒绝并重试一次。
- 在线请求设置 60 秒超时，只对连接异常、408、429 和 5xx 等可恢复问题自动重试一次。
- Codex CLI 仅作为结构化规划提供商运行在临时只读沙箱中，支持当前服务器和已保存服务器两种动作；命令是否审批或执行仍由 OrbitSSH 主进程的三档权限决定。

## 7. 验证

AI 专项测试包含命令策略、数据暴露、提示词注入、脱敏、工具协议、工作目录、执行预算和输入身份校验：

```powershell
npm run test:ai
```

生产构建包含 Vue、Electron TypeScript 检查和 Preload 同步：

```powershell
npm run build
```
